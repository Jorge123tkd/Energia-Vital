# Almacén empresarial — fase de esquema, no activado
La migración 025 añade un libro inmutable de movimientos en la autoridad comercial D1. No modifica artículos, precios ni existencias publicados. El inventario empieza sin artículos y sin saldos: se requiere inventario inicial verificado. Un artículo puede vincularse a un producto comercial o ser interno. Las cantidades se expresan como enteros en milésimas de la unidad fija. Reservar no descuenta físico; entregar a brigada sí, y disminuye la reserva; consumir solo reduce lo entregado; devolver repone físico; liberar elimina reserva. Operaciones limitadas por saldo por proyecto, sin duplicación de ID de movimiento; no se confirma una repetición como éxito sin futura comprobación idempotente del contenido.
El esquema autoriza únicamente administración activa; no hay endpoints ni acceso de brigadas todavía. La API futura debe verificar existencia y asignación del proyecto en Studio, vincular brigadas/órdenes y comprobar idempotencia (mismo ID y mismo contenido) antes de confirmar. Compras, ajuste de inventario auditado, devoluciones a proveedor, contabilidad monetaria, interfaz y reconciliación de stock publicado requieren entregas posteriores. No ejecutar migración en remoto hasta aprobar despliegue; pruebas únicamente datos ficticios.

## Fase 026 — Custodia por trabajo existente
Vinculación inmutable uno a uno entre proyecto Studio y solicitud Bonaire, emitida por un administrador; la existencia real del proyecto debe validarse por servicio Studio antes de insertar (todavía no hay endpoint de enlace). La entrega requiere trabajo programado, brigada activa y solicitud abierta; reserva es por proyecto y custodia por orden existente. Consumo y devolución no pueden usar lo entregado a otra orden, incluso del mismo proyecto. Tras cancelación se permite conciliar lo ya entregado, no nuevas entregas. No se alteran calendario ni reglas de ocupación. Sin API de mutación hasta completar la validación cruzada; migración solo en pruebas, no remoto. Los movimientos de prueba de fase 025 no son datos productivos. Si hubiera movimientos previos a 026, requerir inventario de compatibilidad antes de aplicar.

## API de almacén (gate cerrado)
/api/warehouse/items consulta paginada y alta idempotente de artículos; /projects/:id consulta reserva/entrega; /works/:id consulta custodia; /movements registra recepción, reserva, liberación, entrega, consumo, devolución. Solo administrador central con sesión válida; WAREHOUSE_ENABLED no se define en producción. ID y contenido de movimiento comparados integralmente para reintentos; triggers hacen control de saldo y orden en la misma sentencia. No hay endpoint para crear link hasta validar proyecto comercial con Studio. Sin UI ni cambios a catálogo. Requiere prueba de integración remota y aprobación antes de habilitar.

## Fase 027 — Compras y proveedores
Esquema aditivo de proveedores, pedidos, líneas, aprobación y recepción parcial. Moneda e Incoterm separados; importe contractual por línea en unidades monetarias menores, sin asumir costos de fabricación ni precios minoristas. La recepción es UN movimiento existente del almacén con purchase_line_id, nunca un segundo incremento. No sobre-recepción, pedido cerrado solo si completo, cancelación solo si sin recepción. Faltantes de proyecto calculados sobre necesidad aprobada, reserva, entrega pendiente y consumo. Existencia libre es global compartida, no asignación automática; pedido por recibir no es existencia. Requerimientos son compromisos administrativos separados de ingeniería: no se sincronizan automáticamente; revisión auditada de cambios pendiente. No hay API de compras todavía. Flete, aranceles, costos reales, facturas y pagos en módulo financiero futuro, sin mezclarlos con importe contractual. No ejecutar migración remota.

### API de compras
Bajo /api/warehouse/procurement y el gate cerrado de almacén: proveedores, pedidos con hasta 50 líneas atómicas, decisiones de aprobar/cerrar/cancelar auditadas, recepción idempotente en el mismo ledger y consulta de faltantes. Solo administrador activo. Reintento de creación compara identidad, campos y líneas completas; recepción compara la operación existente. Todavía sin interfaz, alta de necesidad aprobada o enlace remoto de proyecto. No se confirma compra real ni pago por crear pedido. No habilitar hasta pruebas de integración D1 y validación de la cadena completa.
